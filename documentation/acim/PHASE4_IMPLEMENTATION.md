# ACIM Phase 4: implementation

ACIM mode is in the firmware behind a switch that defaults to off. With it off, the only
runtime difference from stock is a few `acim_active()` checks per ISR and one call in the
undriven branch that returns immediately. Nothing has been flashed or run on hardware.

## What was built

| File | What it does |
|---|---|
| `motor/acim_core.c/.h` | Current model (flux in amps, exact discretization, rotated by encoder increments), hybrid voltage/current-model observer, I/f start with handover at 1.2 x and hand-back at 0.8 x `sl_min_hz`, flux state machine (OFF, FLUXING, RUN, HOLD, FAULT), slip clamp and the faults from DESIGN.md section 5. No firmware dependencies. |
| `motor/acim.c/.h` | ISR wrappers, fault reporting through `mc_interface_fault_stop`, the "ACIM" page in VESC Tool with EEPROM storage, `acim_status`, `acim_plot`, `acim_enc_check`, LispBM `acim-flux`, `acim-slip`, `acim-state`, `acim-wr`. |
| `motor/acim_confgen.c/.h` | Generated by `tools/gen_acim_conf.py`: config struct, defaults, serializer, compressed VESC Tool XML. |
| `motor/mcpwm_foc.c` | 12 guarded hooks, listed in DESIGN.md section 3. |
| `datatypes.h`, `motor/mc_interface.c` | `FAULT_CODE_ACIM_FLUX`, `FAULT_CODE_ACIM_SLIP` and their names. |

## How it was checked

- **Builds.** `100_250` and the dual-motor `unity` target build with no warnings.
  `100_250`: flash2 464,672 of 475,120 bytes (97.8%), 14.2 KB more than stock, 10.4 KB left.
- **Firmware core vs simulation.** `sim/check_c_core.py` compiles `motor/acim_core.c` for the
  host and drives it with the Phase 3 motor model in place of the Python controller.
  Results match to the last digit in almost every case (`sim/out/c_core_check.md`):

| Case | Python controller (Phase 3) | C core (firmware code) |
|---|---|---|
| Encoder, tau_r 100%, 150 / 250 / -150 A | 14.35 / 20.48 / -14.39 Nm | 14.35 / 20.49 / -14.39 Nm |
| Encoder, tau_r 70% and 130% | 12.40 / 13.92 Nm at 150 A | 12.40 / 13.93 Nm |
| Flux build-up | RUN after 126 ms | RUN after 126 ms |
| Sensorless nominal | 2.0 deg rms, 1.68 Hz speed error | 2.0 deg, 1.68 Hz |
| Sensorless Rs -30% | 10.3 deg, 6.24 Hz | 10.2 deg, 6.17 Hz |
| Pole pairs 4 / 8 (true 6) | ACIM_FLUX at 0.365 / 0.350 s | ACIM_FLUX at 0.365 / 0.350 s |
| Encoder signal lost | ACIM_SLIP at 1.051 s | ACIM_SLIP at 1.051 s |
| Encoder backwards | no fault, stalls at 114 rpm | same |

- **Config page.** The XML signature uses VESC Tool's algorithm, verified by reproducing the
  signature of the LispBM example config. The serializer round-trips on the host and the
  compressed blob decompresses to `acim_settings.xml`. The page has not been opened in VESC
  Tool yet; that is the first bench step.

## Not checked yet (bench, Phase 5)

- That VESC Tool shows and writes the ACIM page.
- ISR time with ACIM active (expected similar to the PM observer it replaces).
- The voltage timing assumption for the voltage model (DESIGN.md section 3).
- Everything involving the motor.

## Turning it on (for Phase 5, after flashing)

1. Motor config: Motor Type FOC, Sensor Mode **Sensorless**, run "Measure R and L" only,
   conservative current limits, `foc_cc_decoupling` = Cross.
2. ACIM page: set Speed Source (Sensorless until the encoder is fitted), Magnetizing
   Current, Rotor Time Constant, ACIM Current Limit. Then set **Enable ACIM Mode** and write.
3. Terminal: `acim_status` must say "active". With the encoder fitted, run `acim_enc_check`
   first (the motor turns).

`documentation/acim/sim/check_c_core.py` should be re-run after any change to
`motor/acim_core.c`.
